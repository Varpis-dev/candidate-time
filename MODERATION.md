# Установка и повторная модерация

## Настройки карточки приложения

- Адрес приложения: `https://<домен приложения>/`
- Адрес установки: `https://<домен приложения>/install`
- Права: `crm`, `placement`.
- Заявленные встройки: `CRM_LEAD_DETAIL_TAB`, `CRM_DEAL_DETAIL_TAB`, `USERFIELD_TYPE`.
- URL должен указывать на опубликованную версию с этим исправлением. Само изменение GitHub не обновляет карточку приложения в Битрикс24.

## Текст для «Описания процесса установки»

Установку выполняет администратор портала. Во время установки приложение автоматически регистрирует вкладки «Время клиента К2» в карточках лида и сделки (CRM_LEAD_DETAIL_TAB, CRM_DEAL_DETAIL_TAB), тип пользовательского поля candidate_time (USERFIELD_TYPE) и создаёт поле UF_CRM_CAND_TIME в лидах и сделках. Регистрация выполняется до завершения установки, без нажатия кнопок в настройках. Тип поля регистрируется методом userfieldtype.add, который автоматически создаёт встройку USERFIELD_TYPE. Вкладки регистрируются методом placement.bind.

После установки откройте приложение, выберите сущность «Лид», укажите поле города и, при наличии, поле области/региона, нажмите «Сохранить настройки». Повторите настройку для сущности «Сделка». Настройка определяет источники данных для расчёта времени и не является условием регистрации встройки. На вкладках время отображается после выбора источников и заполнения города в карточке. Если вкладка не помещается в строке, найдите её в меню «Ещё». Для отображения пользовательского поля на вкладке «Общие» добавьте созданное поле «Время клиента К2» через настройку карточки CRM.

При ошибке регистрации установка не завершается: отображается причина и кнопка «Повторить установку». Для ранее установленных порталов администратор может открыть приложение и нажать «Восстановить встройки и поля»; эта операция не требует предварительного выбора города и не меняет сохранённые настройки.

## Проверка на двух чистых порталах

1. Убедиться, что опубликована новая версия и адрес установки в карточке заканчивается на `/install`.
2. На первом портале установить приложение администратором, не нажимая кнопку восстановления в настройках.
3. В контексте приложения проверить `placement.get`: обе вкладки зарегистрированы с обработчиком `https://<домен приложения>/field`, `userId: 0`.
4. Проверить `userfieldtype.list`: `USER_TYPE_ID: candidate_time`, обработчик `/field`. Это проверка регистрации USERFIELD_TYPE; отдельный placement.bind для этого типа не требуется.
5. Проверить `app.info`: `INSTALLED: true`, и наличие UF_CRM_CAND_TIME в лидах и сделках с типом `rest_<ID приложения на этом портале>_candidate_time`.
6. Настроить город и регион отдельно для лида и сделки, проверить вкладку и пользовательское поле в обеих сущностях.
7. Повторить шаги на втором чистом портале. ID приложения и пользовательского типа должны соответствовать второму порталу.
8. Нажать «Восстановить встройки и поля» дважды: поля и вкладки не дублируются, ID и значения существующих полей сохраняются.

## Автоматические проверки

`node --test tests/*.test.js` проверяет два независимых контекста порталов, повторную регистрацию, восстановление после частичной ошибки, отсутствие ложного завершения установки, миграцию обработчика, пагинацию, сохранность чужого поля и контекст сделки во вкладке. Тесты используют имитацию API; фактическую установку на чистых порталах нужно проверить отдельно.
